今天要分享的，就是怎麼從「一個 AI 工具」走到「一個 AI 部門」。

Chatbot → Tool-Use → Agent

💬
Chatbot — 你問一句，它答一句 （大部分人對 AI 的認知）
🔧
Tool-Use AI — 能呼叫工具：搜尋、寫檔、查資料庫 （ChatGPT Plugins）
🤖
Agent — 有記憶、有排程、能主動做事、能跟其他 Agent 協作
關鍵差異：Agent 不需要你每次下指令。它會自己判斷什麼時候該做什麼，像一個遠端同事。

為什麼要多個 Agent

🧠
專注度 — 一個 Agent 什麼都做，context 會爆。分工後各專注自己的領域
💰
成本控制 — 簡單任務用便宜模型，複雜的用強模型
🔒
權限隔離 — 財務 Agent 看不到客服資料，天然安全邊界
📱
多頻道 — 不同 Agent 綁不同通訊管道，切換頻道 = 切換 Agent

怎麼運作的

人格、記憶、Skill、排程

Agent 的工作空間 — 一切從 .md 開始

# OpenClaw 初始化時自動生成的檔案結構 workspace/ ├── BOOTSTRAP.md # 🐣 出生儀式（用完即刪） ├── SOUL.md # 🧠 人格與價值觀 ├── IDENTITY.md # 🪪 名字、物種、emoji ├── USER.md # 👤 主人是誰 ├── AGENTS.md # 📋 行為規範與 SOP ├── TOOLS.md # 🔧 環境筆記（SSH、裝置） ├── HEARTBEAT.md # 💓 空閒時的巡邏清單 ├── MEMORY.md # 📝 長期記憶（精華） └── memory/ # 📅 每日筆記
🐣
BOOTSTRAP.md — 第一次啟動時 Agent 跟你聊天：「我叫什麼？什麼個性？」聊完自動生成 SOUL.md，然後刪除
✨
全部有預設模板 — openclaw init 自動生成，修改 .md 就能自訂
換一組 .md 檔案 = 換一個完全不同的 Agent。不用改程式，不用重新訓練

SOUL.md — 賦予 Agent 人格

# SOUL.md — 情報分析師 ## 身份 你是情報分析師，負責每日新聞摘要。 個性直接，嗅覺敏銳。 ## 說話風格 - 條列式，每條附來源連結 - 不確定的事標註「未經證實」 - 用繁體中文，不閒聊 ## 工作範圍 - AI 產業動態 - 國際重大事件 - 技術趨勢
🧠
Agent 每次啟動都讀 SOUL.md — 像人的性格
🎭
不同 Agent 寫不同 SOUL.md = 不同角色
✍️
第一次啟動時 Agent 自己寫出 SOUL.md — 你只需要聊天描述角色
換一組 .md 檔案 = 換一個完全不同的 Agent。不用改程式，不用重新訓練。
延伸應用：讓 Agent 用各自人格在社群平台自動發文互動——不只好玩，也是 LLM 長期行為一致性的壓力測試。

三層記憶架構

MEMORY.md — 長期記憶
提煉後的精華：決策、偏好、教訓
↓
memory/YYYY-MM-DD.md
每日原始記錄
↓
memory_search — 語意檢索
Embedding 搜尋，跨檔案找相關內容
📖
每次啟動讀今天 + 昨天的筆記
✍️
重要事件即時記錄
🔄
凌晨自動回顧 + 提煉精華
Agent 每次重啟都失憶。記憶系統就是它的延續性。

Skill — 教 Agent 用工具

# 每日情報摘要 Skill ## 觸發條件 每天 07:30 自動執行 ## 步驟 1. 用 web_search 搜尋關鍵字 2. 用 web_fetch 抓取內容 3. 結構化整理成摘要 4. 發送到指定頻道 ## 輸出格式 🔹 **類別**：標題 + 一句摘要 連結：原始 URL ## 注意事項 - 每條必須附原始連結
📄
Skill = 一份 SKILL.md + 腳本 + 參考資料
🤖
Agent 根據任務自動選擇要用哪個 Skill
📝
LESSONS.md — Agent 踩坑後自己記下來，下次不再犯
Skill 就像 SOP 文件——告訴 Agent「遇到這種任務，照這個流程做」。

Skill 生命週期 — Model 互補

🤖 主 Agent
撰寫第一版 Skill
→
🤖 執行 Agent
實際跑任務
→
📝 踩坑
寫入 LESSONS.md
→
🔄 下次更好
自動參考教訓
🤖 強模型（Opus）
理解意圖、設計流程、撰寫 Skill 初版。
擅長全局規劃和複雜推理。
🤖 輕模型（Sonnet / GPT）
照 Skill 重複執行。速度快、成本低。
踩坑都記進 LESSONS.md。
Skill + LESSONS.md 讓便宜模型也能做出強模型品質的工作——因為經驗都寫在檔案裡。

怎麼開始

從你的工作流程出發

第一步：盤點你的工作流程

不是「AI 能做什麼」，而是「你每天在重複什麼」。
把日常工作拆成步驟，標記哪些是重複性的。
步驟內容性質AI？
1收到新資訊（信件 / 公告）被動接收✅ 自動監控
2整理摘要、擷取重點重複性✅ 結構化輸出
3判斷優先順序 / 決策需要判斷👤 人類
4執行動作（回信 / 建檔）重複性✅ 自動執行
5追蹤進度、定期回報重複性✅ 排程巡檢
🎯
重複性高 + 規則明確的步驟 = AI 的切入點

第二步：把流程變成 Skill，迭代改進

📝 寫 Skill
第一版不用完美
→
▶️ 讓 Agent 跑
觀察實際行為
→
👀 看哪裡不對
輸出格式？遺漏？
→
✏️ 修改 Skill
補規則、加範例

❌ 以前（手動）

1
早上打開 20 個網站看新聞
2
逐篇閱讀、整理成摘要
3
每天花 30-60 分鐘

✅ 現在（Skill 自動化）

1
寫一份情報蒐集 Skill
2
設定 Cron 每天 07:30 執行
3
起床就看到結構化摘要
💡
大概 3-5 次迭代，一個 Skill 就能穩定運作。之後就是全自動。

安全與踩坑

實戰中學到的事

安全 — 最重要但最容易忽略

💉
Prompt Injection — 惡意指令藏在信件 / 網頁裡，Agent 讀取後被誘導
🔐
權限隔離 — 每個 Agent 只能存取需要的資源，最小權限原則
📝
稽核日誌 — 所有行為可追蹤、可回溯
👤
Human-in-the-loop — 破壞性操作（刪除、發送、金錢）一律需確認
Peter：「如果你確保只有你自己能跟它說話、不把東西放公網上，風險就小很多。」
— Lex Fridman Podcast #467

踩過的坑

Context Pollution
Agent A 讀到 Agent B 的日誌，把別人的經歷當成自己的
→ 記憶需按 Agent 過濾，段落級隔離
角色漂移
GPT 系列容易忘記人格設定，講到一半變通用助手
→ 加 few-shot 範例固定風格 · Claude 天生較穩定
靜默失敗
Agent 做完工具呼叫但不回報結果，以為自己已經回覆了
→ 指令中明確要求「做完要回報」+ 主動設計監控
最大的教訓：Agent 不會主動告訴你它搞砸了。需要主動設計驗證機制。

總結

01
AI Agent ≠ Chatbot — 有記憶、有排程、能主動做事的數位同事
02
Multi-Agent 分工 — 每個 Agent 專注一件事，比全能 Agent 更可靠
03
Skill + LESSONS.md — 把 SOP 寫成 Skill，讓 Agent 自己累積經驗
04
Model 互補 — 強模型設計、輕模型執行，成本和品質兼得
05
從你的工作流程開始 — 找到重複的步驟，那就是切入點
